# 構想メモ: re:Invent Radar（新機能・新セッションの自動検知と解説）

- 起票: 2026-10-06
- 状態: 構想のみ。未着手
- 位置づけ: セッションマップ（このリポジトリ）とは別アプリにする

## やりたいこと

re:Invent 期間中は新機能・新 API・新セッションが短時間に大量に出る。これを自動で拾い、読む・書く手間を減らす。

1. 新機能・新 API を定期的に検知する
2. 新機能には、日本語の解説を自動で付ける
3. 期間中に追加された新規セッションを検知し、案内する
4. AI エージェント関連の新機能は、解説に加えてブログ（Qiita）の下書きまで AI で作る

## 別アプリにする理由

- セッションマップはブラウザだけで動く静的アプリ。定期実行と LLM 呼び出しにはサーバー側の常駐処理が要る
- 監視側の障害を、会場で使う地図アプリに波及させない
- 連携は「新規セッションの一覧」を API かファイルで渡す形にとどめる。セッションマップ側はそれを読んで「NEW」印を出すだけにする

## 情報源（候補。URL と形式は着手時に要確認）

| 対象 | 情報源 | 取得頻度の目安 |
|------|--------|----------------|
| 新機能 | AWS What's New の RSS | 15 分ごと |
| 新機能（詳細） | AWS News Blog の RSS | 30 分ごと |
| 新 API | AWS SDK のリリースノート、または botocore のサービス定義の差分 | 1 時間ごと |
| 新規セッション | 公式カタログ API（`scripts/fetch-catalog.mjs` と同じ取得方法）の sessionID の差分 | 1〜3 時間ごと。間隔を空けて負荷をかけない |

## 処理の流れ（案）

1. EventBridge Scheduler が Lambda を定期起動する
2. Lambda が各情報源を取得し、DynamoDB の既読 ID と突き合わせて新着だけを抜き出す
3. Bedrock の Claude で分類する: 新機能 / 新 API / 新規セッション、AI エージェント関連かどうか
4. 新機能 → 日本語の要約と解説を生成する。出典 URL を必ず付ける
5. 新規セッション → 日時・会場・形式・録画の有無の見込みを添えて案内する。マイプランの空き時間に入るかも判定できるとよい
6. AI エージェント関連 → 解説に加えて、Qiita 記事の下書きを Markdown で生成する
7. 結果をフィードに載せ、スマホに通知する

## 下書き生成のルール

- 公開は自動で行わない。下書きは S3、または Qiita 用リポジトリの下書きブランチに置くだけ。投稿は八雲が確認してから行う
- 文体は `write-qiita` / `writing-guide` スキルに従う
- 一次情報（What's New・公式ドキュメント・API リファレンス）だけを根拠にし、出典 URL を本文に入れる
- 実際に触っていない挙動は書かない。書く場合は「未検証」と明示する
